31 August 2026. Supersedes every earlier copy.

This file is a readable mirror of src/forge-theme.css. That file is the source

────────────────────────────────────────────────────────────────────────────
1. THE MARK
────────────────────────────────────────────────────────────────────────────

An angular F, cut on the diagonal, in three facets: the two arms in the brand
colour, the stem's upper wedge in near-white, its lower wedge in grey. It sits
on a charcoal tile with a long 45° shadow falling to the lower right.

  brand/forge-logo.svg    faceted, full colour
  brand/forge-mark.svg    flat silhouette, currentColor — for masks and icons
  brand/source-logo.png   the original raster the vectors were traced from

Everything Forge ships is generated from those two SVGs by

  python3 tools/make-icons.py

which writes public/icons/<accent>/ for all five accents, mirrors the default
into the paths index.html and the manifest reference, and rebuilds favicon.ico
and every iOS size. Nothing is hand-drawn at a pixel size — that is how icon
sets drift apart.

IN THE APP the mark is a CSS mask (--forge-mark), so it is one flat colour, and
that colour is --accent-text. A solid brand-blue mark on white is a smudge;
--accent-text is the same hue at a value that survives both grounds.


────────────────────────────────────────────────────────────────────────────
2. THE ONE RULE
────────────────────────────────────────────────────────────────────────────

Nothing in Forge names a colour. Everything names a ROLE, and the role resolves
from the athlete's tone and accent.

    background: var(--surface-1);     ← correct
    background: #1b2223;              ← wrong, even if it looks identical

ONE file contains colour literals: forge-theme.css, which defines the roles.
forge-grounds.css holds more, but it is generated from them. Every other
stylesheet in the app — all 45 — is roles only, including appearance.css, whose
swatches used to be the one honest exception and now read the real ladders
through data-ground and data-force-tone instead.


────────────────────────────────────────────────────────────────────────────
3. FOUR AXES
────────────────────────────────────────────────────────────────────────────

  TONE      light · system · dark            how bright the app is
  GROUND    carbon · midnight · ink · espresso     what the neutrals are made of
  ACCENT    signal · flare · coral · amber · tide · harbor
  ICON      match · any accent               what sits on the home screen

They are independent and they compose: 3 × 4 × 6 × 7 = 504 finished looks from
one set of components. This replaced five "UI packages" that were 5 looks from
five parallel palettes, none of which was ever finished.

TONE AND GROUND ARE DIFFERENT QUESTIONS, which is why they are different
controls. Tone is how much light is in the room. Ground is what the app is
built out of. And because every ground reuses the same rung LIGHTNESSES and
moves only hue, choosing one can never make anything harder to read — see §4.

How tone reaches CSS:

    <html data-theme="light">    the athlete chose light
    <html data-theme="dark">     the athlete chose dark
    <html>  (no attribute)       System — prefers-color-scheme decides

Dark is declared TWICE in forge-theme.css: once under
@media (prefers-color-scheme: dark) guarded by :root:not([data-theme="light"]),
and once under :root[data-theme="dark"]. The first makes System follow the OS;
the second makes an explicit dark choice beat a light OS. A token that exists in
one tone and not the other is a bug.

How ground reaches CSS: <html data-ground="carbon">. Carbon is the bare tone
blocks in forge-theme.css; the other three are generated into
src/forge-grounds.css by tools/build-grounds.py.

How accent reaches CSS: <html data-accent="signal">. Each accent block declares
its values TWICE — --a-text for a light ground, --a-text-d for a dark one — and
declares nothing else. The tone blocks pick which half is live. Components never
read an --a-* variable; those are raw material, not roles.

[data-accent] on any element scopes a different accent to that subtree while
keeping the page's tone. The settings screen uses it so every accent chip is
painted from the real tokens instead of a hand-picked stand-in.

[data-ground] scopes a ladder the same way, and [data-force-tone="light"|"dark"]
puts the OTHER tone's ladder on an element — that is how the settings screen
shows you a tone and a ground you are not currently in without a single
hardcoded hex.

Stored under localStorage key `forge-appearance-v5` as
{ theme, ground, accent, icon } and mirrored to the athlete's account.
index.html reads it inline before first paint, so there is no flash of the
wrong ground OR the wrong colour on a cold open. Each key bump added an axis
rather than changing one, so an older record is a valid partial and merges
forward.

RETIRED ACCENTS. The first set (ember, volt, sand, slate) was invented before
Preston's secondary palettes existed. Each retires to its nearest survivor —
ember→coral, volt→amber, sand→harbor, slate→harbor — in BOTH the head script
and the provider, so the first painted frame is the same colour as the second.
Nobody opens the app to a colour they did not pick.

4. GROUND — the neutrals
────────────────────────────────────────────────────────────────────────────

CARBON is the reference ladder, and every other ground is derived from it.

                          LIGHT          DARK
  --bg                    #f3f5f5        #131819
  --surface-1             #ffffff        #1b2223     a card on the ground
  --surface-2             #e8ecec        #252e2f     a control on a card
  --surface-3             #dbe1e1        #3f4849     hover, active chip
  --surface-sunken        #eaeeee        #0d1213     an inset well, a track
  --hairline              #dce2e2        #2c3435
  --hairline-strong       #bac3c3        #4a5556
  --ink                   #14181a        #edf1f1
  --ink-2                 #454c4b        #b9c1c0
  --ink-3                 #5f6563        #939997
  --grid-line             rgba(20,24,26,.035)   rgba(255,255,255,.035)

  #3f4849 — the charcoal the mark sits on — is --surface-3, the step a thumb
  actually touches. The page goes DEEPER than the logo's ground on purpose: at
  #3f4849 the brand blue reaches only 3.1:1, and no amount of care elsewhere
  fixes a ground that is too close to the thing on it.

  The palette's #7b807e is NOT in the ink ladder. It carries 4.0:1 on white and
  3.0:1 on --surface-3, and a rendered audit found it under every calendar
  date, timestamp and caption in the app. "Tertiary" is a rank, not permission
  to be unreadable. #7b807e keeps its job in the mark.

THE OTHER THREE ARE GENERATED, and the rule that generates them is the whole
reason this system holds together:

  Held constant per rung:  OKLab L, taken from Carbon
  Varied per ground:       hue, and a chroma budget

So Midnight's card is exactly as light as Carbon's card, and any colour that
clears 4.5:1 on one ground clears it on all four. Without that constraint every
new ground would need its own accent set — the packages problem wearing a hat.

                    hue    chroma   dark --bg   light --bg
  carbon            205    0.010    #131819     #f3f5f5
  midnight          255    0.042    #09172a     #eef5fe
  ink               250    0.008    #14171b     #f3f5f6
  espresso           27    0.030    #23110f     #fcf2f1

Text rungs take half the chroma; light surfaces take a third, because coloured
paper is a different and worse idea than a tinted ground. --surface-1 is
#ffffff on every ground: there is no room at L=1 for a tint, and pushing one in
only bends the colour out of sRGB.

  python3 tools/build-grounds.py

regenerates src/forge-grounds.css. It REFUSES TO WRITE if any rung drifts in
real luminance or if any accent's type falls under 4.5:1 on any ground. OKLab is
load-bearing: in HSL two colours with the same "lightness" can differ by a third
of a stop in real luminance, and ladders built that way drift.

STATUS AND DATA are tone-level, not ground-level — they mean the same thing
whatever the app is built out of.

                          LIGHT          DARK
  --good                  #1f7a3d        #58d68d
  --warn                  #8a5a00        #f6c453
  --bad                   #b3261e        #ef8a7b
  --info                  #6d4ac4        #b49bff
  --chart-2               #c2410c        #fb923c
  --chart-3               #6d4ac4        #b49bff
  --chart-4               #0f7d74        #5fe0c6
  --chart-5               #8a5a00        #f6c453
  --chart-6               #b3261e        #ef8a7b

  --chart-1 follows the accent. --info is violet, not blue: it marks forecasts
  and the coach's guesses, and with a blue accent a blue info is invisible on
  exactly the charts where the distinction matters.


INVERTED SURFACES — tooltips and toasts contrast with content, not match it
  --inverse-surface       #14181a        #edf1f1
  --inverse-ink           #f3f5f5        #131819

DEPTH
  --shadow-1              0 1px 2px rgba(20,24,26,.06)    0 1px 2px rgba(0,0,0,.40)
  --shadow-2              0 6px 18px rgba(20,24,26,.09)   0 6px 20px rgba(0,0,0,.45)
  --shadow-3              0 18px 44px rgba(20,24,26,.16)  0 18px 48px rgba(0,0,0,.60)
  --shadow-color          rgba(20,24,26,.14)              rgba(0,0,0,.45)
  --overlay               rgba(20,24,26,.38)              rgba(0,0,0,.66)
  --scrim                 rgba(20,24,26,.46)              rgba(0,0,0,.72)
  --lift                  #14181a                         #ffffff
  --page-glow             transparent                     var(--accent-wash)

  --lift is the tint mixer. Components lift a surface by mixing white into it,
  which separates on charcoal and does nothing on white; --lift is whichever
  direction actually separates, so
  `color-mix(in srgb, var(--surface-1) 96%, var(--lift))` reads in both.


────────────────────────────────────────────────────────────────────────────
5. ACCENT — seven values, twice each
────────────────────────────────────────────────────────────────────────────

  --a-fill     the brand colour. Borders, indicators, chart lines.
  --a-strong   a FILLED control, with --a-ink on top.
  --a-ink      text sitting on --a-strong.
  --a-text     the accent used AS TEXT on a page ground.
  --a-dim      disabled states, gradient ends.
  --a-tint     the hue washes mix FROM.
  --a-chart    data series 1.

WHY --a-strong EXISTS. #259de2 carries exactly 3.0:1 against white. White text
on it fails; charcoal text on it fails at 3.1:1; there is no ink that works. So
a filled button in light tone is the deeper #1571ae with white, and in dark tone
the brand blue itself with near-black. You only ever see one tone, so the button
reads as one colour, correctly, in both.

EVERY VALUE EXCEPT --a-fill IS SOLVED, NOT PICKED. tools/solve-accents.py walks
OKLab lightness along the accent's own hue until the value clears its contrast
requirement, and stops at the first one that does — so each is the closest
version to the brand colour that the job allows, rather than "a darker blue"
chosen by eye. --a-text is measured against --surface-2, the DARKEST light
surface type lands on; solving against white is how you ship an accent that
looks fine on the page and fails on a card.

WASHES ARE DERIVED, NOT DECLARED
  --accent-wash          color-mix(in srgb, var(--tint) 10%, transparent)
  --accent-wash-strong   color-mix(in srgb, var(--tint) 18%, transparent)

ADDING AN ACCENT

  1. put the brand hex in tools/solve-accents.py and run it; it prints the
     CSS block and the ACCENT_TEXT entry
  2. paste both, and run tools/build-grounds.py — it re-verifies the new
     accent against all four grounds and refuses to write if it fails
  3. add it to accentChoices and the head script's regex in index.html
  4. run tools/make-icons.py for its icon set
  5. run `node contrastcheck.mjs` — the rendered audit, 144 page loads across
     tones, grounds and accents — and ship only on a clean run

The entry requirement is not negotiable: --a-ink clears 4.5:1 on --a-strong and
--a-text clears 4.5:1 on every surface it can land on, in both tones, on every
ground. An accent that cannot be read is a decoration, and this app is read at
5am and mid-set.

BRAND COLOURS THAT ARE NOT OURS — never tokenised, never theme-flipped

  Google blue             #4285f4
  Google button           #ffffff ground, #1f1f1f text, #dadce0 border
  Apple button            --ink ground, --bg text (required to be at least as

────────────────────────────────────────────────────────────────────────────
6. TYPE
────────────────────────────────────────────────────────────────────────────

  --display   'Archivo', 'Helvetica Neue', Arial, sans-serif
  --body      'Inter', system-ui, -apple-system, sans-serif

Loaded in index.html <head> with preconnect to fonts.gstatic.com:
  Archivo   500 600 700 800
  Inter     400 500 600 700 800

Archivo is a grotesque built for headlines AND small text: squarer, more
engineered, with real mass at 700–800 without narrowing. It answers the mark,
which is all straight cuts and hard angles. Inter stays for body and data —
best tabular figures of any free UI face, and this app is mostly numbers in
columns.

USAGE
  Display    page titles, big numbers, metric values, avatar initials.
             800 weight, uppercase, letter-spacing .01–.02em.
  Body       everything else. 400–600.
  Eyebrows   11px, 800, letter-spacing .14em, uppercase, --ink-2.
  Data       Inter with font-variant-numeric: tabular-nums.

Inputs never go below 16px — anything smaller makes iOS Safari zoom the page.

  --r-pill 999px    --s5 22px
                    --s6 30px

Tone changes are NOT animated. A 150ms colour crossfade across every surface on
the page reads as a glitch, not a transition.


────────────────────────────────────────────────────────────────────────────
8. LEGACY ALIASES
────────────────────────────────────────────────────────────────────────────

Older stylesheets read these. They point at the new roles so nothing had to be
converted twice. Do not use them in new code.

  --panel → --surface-1      --text  → --ink        --gold → --accent
  --panel-2 → --surface-2    --muted → --ink-2      --mint → --good
  --line, --border → --hairline                     --card → --surface-1
  --success → --good         --warning → --warn     --radius-ui → --r-md
  --accent-contrast → --accent-ink
